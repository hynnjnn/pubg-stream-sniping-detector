# PUBG API 기반 스트림 스나이핑 실태 조사 및 시각화 보고서

## 1. 문제 정의 (Problem Statement)
글로벌 라이브 스트리밍 산업의 지속적인 성장과 함께, 인플루언서(스트리머)가 게임 IP의 흥행과 유저 유입에 미치는 영향력이 매우 커졌다. 그러나 의도적으로 방송을 보며 스트리머와 동일한 매치에 진입해 게임 플레이를 방해하고 괴롭히는 저격(Stream Sniping) 행위가 꾸준히 심각한 문제로 이어지고 있다.

지속적인 저격 행위는 스트리머의 콘텐츠 생산 동기를 저하시켜 방송 중단(이탈)으로 이어진다. 실제로 2026년 4월, 세계 최대 규모의 스트리머인 'Ninja'(팔로워 1,930만 명)가 신작 게임 방송 중 지속적인 스트림 스나이핑과 치팅 공격에 "게임이 사실상 플레이 불가능한 수준"이라며 무기한 휴방을 선언한 사건이 발생하기도 했다.

이와 같은 대형 인플루언서의 이탈은 스트리머를 통해 유입되던 시청자 및 일반 유저층의 연쇄적인 부정적 인식 형성 및 게임 이탈(Churn)을 유발하며, 최종적으로 게임사의 브랜드 가치 훼손과 매출 감소라는 비즈니스 리스크를 초래한다. 본 분석은 특정 스트리머의 실제 배틀그라운드 인게임 텔레메트리(Telemetry) 데이터를 기반으로 이처럼 게임 생태계를 위협하는 저격 행위의 정량적 실태를 조사하고 시각화로 입증하고자 시작하게 되었다.

## 2. 분석 과정 (Analysis Process)

### [데이터 수집: PUBG API 활용]
* 🌐 **PUBG Developer Portal:** https://developer.pubg.com/

크래프톤 공식 PUBG API 텔레메트리 엔드포인트(JSON). 타겟 스트리머(50091kg)의 최근 20매치 리스트를 추적하여 매치당 평균 약 115만 줄에 달하는 대용량 로그 데이터를 수집·적재하였다. 

### [데이터 정제: 불필요한 데이터 삭제]
* **이벤트 필터링:** 플레이어의 위치 좌표 정보를 포함한 이벤트인 `LogPlayerPosition` 데이터만파싱
* **매치 유효성 검증:** 인게임 로그 분석 결과 스트리머의 매치 참여 로그는 존재하지만 탈주 등의 이유로 스트리머의 인게임 로그가 존재하지 않는 무의미한 1개 매치 발견 -> 해당 케이스 예외처리 로직 구현
* **대기실 데이터 제외:** 게임 시작 전 유저들이 밀집되어 있는 대기실에서의 데이터가 거리 계산 왜곡을 일으키는 것을 확인 -> 게임 상태값 변수인 `isGame` 컬럼을 활용하여, 매치 시작 전 대기실 및 비행기 탑승 이동 경로 데이터(`isGame < 0.5`)를 필터링
* **시점 동기화:** 스트리머가 사망한 시점 이후의 타임스탬프 로그를 일괄 제거하여, 저격 대상이 사라진 시점 이후의 무의미한 데이터가 분석 결과에 노이즈를 일으키지 않도록 처리

### [비동기 시계열 데이터 거리 계산: pd.merge_asof 활용]
배틀그라운드 텔레메트리의 위치 로그는 개별 플레이어의 진입 시점을 기준으로 각각 10초 간격으로 기록되는 것을 확인할 수 있었다. 이로 인해 플레이어 간 타임스탬프가 초 단위로 일치하지 않는 '시계열 비동기화 문제'가 발생하였고, 일반적인 Pandas의 `merge` 함수로는 스트리머와 유저 간의 정확한 거리 계산에 한계가 있었다.

이를 해결하기 위해 Pandas의 `merge_asof`함수와 `direction='nearest'` 옵션을 활용하여 각 유저의 로그 시간과 가장 가가운 스트리머의 위치 데이터를 매칭하여 거리를 계산할 수 있었다. 또한 `tolerance=pd.Timedelta(seconds=12)` 옵션을 통해 허용 오차를 12초로 두고 이를 초과한다면 거리 계산 제외 및 콘솔에 해당 사항을 출력하도록 처리하였다. 

> **12초 설정의 이유:** 배틀그라운드 위치 로그의 평균 생성 주기가 약 10초 내외라는 도메인 지식을 바탕으로 설정. 시간 제한 없이 무조건 가장 가까운 시점을 매칭하게 되면, 네트워크 지연이나 로딩으로 인해 로그가 누락된 구간에서 과거 혹은 미래의 무의미한 좌표와 강제 매칭되어 왜곡되는데, 이것을 막기 위해 설정하였다.

## 4. 한계점 및 확장 계획 (Limitations & Future Work)

### [한계점 (Limitations)]
* **고의성 입증의 한계:** 스트림 스나이핑은 유저의 '의도(고의성)'에 기인하므로, 순수한 데이터 분석만으로 이를 100% 단정하기 어렵다는 본질적인 한계가 존재한다. 예를 들어, 인기 있는 랜드마크나 자기장 중심부로 이동하는 과정에서 일반 유저가 우연히 스트리머와 동선이 겹친 경우를 정교하게 구분하기 쉽지 않다. 실제로 다른 스트리머에 대한 시각화를 진행했을 때, 사녹(맵)만 하는 유저가 저격 의심 유저 랭킹 순위권에 위치해 있었다.
* **API 호출 제한:** 현재 개발 환경에서는 PUBG 공식 API의 호출 제한(분당 10건)으로 인해, 더 방대한 기간의 매치 데이터를 실시간으로 전수 조사하거나 실시간으로 대시보드에 반영하는 데 기술적 한계가 존재했다.
* **지능형 저격 유저 식별의 어려움:** 본 분석 결과처럼 단기적으로 노골적인 저격을 행하는 유저 외에도, 제재 시스템의 레이더를 피하기 위해 의도적으로 매치 진입에 텀(Gap)을 두고 가끔씩 괴롭히는 지능형 저격 유저들의 경우 현재의 일차원적인 계산 방식으로는 완벽히 포착하기 어렵다.

### [후속 확장 계획 (Future Work)]
* 본 프로젝트를 통해 구축한 '작동 가능한 데이터 정제 및 동선 동기화 파이프라인 샘플'을 기반으로 크래프톤 API 개발 부서에 공식적인 Rate Limit(요청 제한) 상향 조정을 요청할 계획이다.
* API 호출 제한 문제가 해결되면 저격 의심 유저 각각에 대한 디테일한 분석이 가능해진다. 예를들면 스트리머가 사망했을 때, 다음 매치도 저격하기 위해 게임에서 이탈했인지, 텔레메트리 데이터에서 `LogPlayerAttack`, `LogPlayerTakeDamage`도 활용 해서 직접적으로 스트리머에게 해를 가하거나, 심지어 스트리머가 타고있는 차의 바퀴를 깼는가에 대한 디테일한 분석도 가능해질 것으로 기대된다.
* 이러한 로직을 통해 의심 유저에 대한 저격 위험도 인덱스를 산출할 예정이다. 이를 스트리머들이 관리하는 '저격 의심 유저 명단'과 연계하여 PUBG의 실무 부서가 신속하고 공정하게 의사결정을 내릴 수 있도록 돕는 보조 지표로 고도화하는 것이 최종 목표가 될 것 같다.
